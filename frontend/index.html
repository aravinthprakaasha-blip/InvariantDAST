01 — The problem

        
Generic scanners see endpoints. Attackers see workflows.

        
Travel APIs are deeply stateful. Hit /bookings/{id}/refund without a ticketed booking and you get a 404, not a finding. So conventional DAST drowns you in syntax noise and never reaches the logic that loses money.

      

      

        

          
Conventional DAST

          
    
            
  • ✕Treats every route as stateless and isolated
    • 
            
  • ✕Sprays SQLi / XSS payloads at JSON bodies
    • 
            
  • ✕Hours-long scheduled scans, whole-app every time
    • 
            
  • ✕LLM "maybe-vulnerable" guesses, triage fatigue
    • 
            
  • ✕Leaves orphaned holds and locked inventory behind
    • 
            
  • ✕Vague PDF reports nobody actions

    •

    03 — Near-real-time triggering
    
        
    Test what changed. In minutes, not hours.
    
        
    A commit, a frontend bundle rebuild, or a gateway route change triggers a run. The blast-radius analyzer diffs the AST, follows call graphs to downstream dependents, and schedules only the state paths that touch them.
    
        
      
          
    • Webhooks for GitHub, GitLab, Bitbucket and gateway config
      • 
          
    • Call-graph traversal across services and shared modules
      • 
          
    • Unchanged paths reuse their last verified result

    05 — Dual-Persona Differential Oracle
    
        
    Proof, not probability.
    
        
    Two isolated, low-privilege tenants. Agency A creates a real booking; Agency B tries to read or change it. A deterministic structural JSON diff against B's own baseline decides — no language model gets a vote.

    06 — Compensating Transaction Engine
    
        
    Aggressive tests. Zero operational residue.
    
        
    Every mutating request is linked to its compensating action before it is sent. Holds are cancelled, seats released, test refunds reversed. Circuit breakers watch wallet balance and inventory so a test run can never exhaust credit or lock a flight.
    
        
      
          
    • Saga log with X-Invariant-Trace on every request
      • 
          
    • Adaptive rate limiting with exponential back-off
      • 
          
    • Hard stops on balance, seat-lock and error-rate thresholds

      07 — Developer-ready remediation
      
        
      Not an alert. A pull request.
      
        
      Each verified finding ships as a bundle: a minimal reproducible curl script, the business impact in plain terms, and an exact patch. On the next commit the proof-of-concept re-runs automatically and closes the loop.

      # INV-0231 — cross-tenant booking read (BOLA)
# 1. Agency A creates a hold
BK=$(curl -s -X POST $API/bookings/hold \
  -H "X-Agency-ID: AGY-A" \
  -d '{"quote_id":"'$QUOTE_A'"}' | jq -r .booking_id)

# 2. Agency B reads it — expected 403
curl -s $API/bookings/$BK -H "X-Agency-ID: AGY-B"
# → 200 OK  {"booking_id": "...", "agency_id": "AGY-A", ...}

# 3. Compensation
curl -s -X POST $API/bookings/$BK/cancel -H "X-Agency-ID: AGY-A"
      
        
      
        
      
          
      
            
      What an attacker gets
      Any agency on the platform can enumerate other agencies' bookings: passenger names, itineraries, fares and markups.
      
            
      Business exposure
      Passenger PII disclosure across tenants, competitive leakage of negotiated fares, likely GDPR / DPDP notification event.
      
            
      Exploitability
      Single unauthenticated-to-tenant request; booking IDs are leaked in amendment emails.
